# 02 결정 기록

| 항목 | 값 |
|---|---|
| 기간 | 2026-11-18 ~ 2026-11-25 |
| 형식 | 결정마다 고민 → 후보 → 고른 것 → 이유. 검토한 다른 안도 함께 적는다 |

## D-01 소재: 내가 실제로 하는 일에서 고른다 (11/24)

- **고민:** 혼자 서비스를 하나 실제로 출시하고, 데이터를 보고 고치는 사이클을 돌려 보고 싶었다.
- **고르는 기준:** 코드부터 쓰지 않는다. ① 이걸 쓰면 무엇이 해결되나 ② 왜 다시 오나 ③ 내가 실제로 겪는 일인가 ④ 결과를 캡처해 올리고 싶은가를 먼저 본다.
- **고른 것:** 내가 실제로 하는 직관 기록. 시즌 중인 농구 · 배구를 앞에 두고 국내 프로 리그 전체로. 종목이 늘어도 만드는 일은 팀 목록이 느는 정도이고, 계절이 이어져 1년 내내 쓸 이유가 생긴다.
- **형식:** 앱인토스. 웹은 사람을 데려오기가 가장 어려운데 토스 안에는 이미 사람이 있다. 사업자 없이 시작할 수 있다.

## D-02 판정 기준: 내 승률이 아니라 팀 성적 대비 (11/24)

- **고민:** 처음엔 내 승률만으로 판정했다(70% 이상 승리요정 등). 그러면 원래 강한 팀 팬은 누구나 승리요정이 된다.
- **고른 것:** 팀 시즌 승률 대비 차이(%p). 예: 팀 시즌 45%인데 내가 간 날 75%면 +30%p.
- **이유:** "진짜" 승리요정을 가려야 판정에 의미가 생기고, 공유 문장도 강해진다("팀은 45%인데 내가 가면 75%").
- **생긴 문제와 해결:** "8승 3패인데 왜 보통이냐"는 혼란이 생겼다. 기준은 차별점이라 그대로 두고, 판정 아래 **이유 문장**을 붙였다("팀이 원래 강해요. 딱 그만큼 이겨요").

## D-03 입력: 결과를 직접 고르기 → 공식 결과 자동 반영 (11/24)

- **고민:** 이겼어요 / 졌어요를 직접 고르게 하면 입력이 길고, 몇 번 갔는지 세는 것 자체가 어렵다.
- **고른 것:** 팀을 고르면 경기 목록이 열리고, 고르면 공식 결과가 채워진다. 최근에 안 적은 경기 4개를 바로 펼친다.
- **이유:** 사용자에게 떠올리게(회상) 하지 말고 알아보게(인식) 한다. 첫 방문에 지난 경기를 체크만 하면 바로 판정을 받는다.
- **이어진 결정:** 결과를 언제 가져오나 → "경기 시작 + 경기 길이가 지났는데 결과가 비어 있을 때만" 그 리그 공식 누리집을 확인하는 수집기를 만들었다(10분 간격, 매일 새벽 전체 갱신).

## D-04 데이터 출처: 공식 누리집만 (11/24)

- **검토한 안:** 포털 스포츠 순위를 자동 수집. 포털 약관이 자동 수집을 금지한다.
- **고른 것:** 각 리그 공식 누리집만, 경기가 끝났을 때만 접속, 출처 표시, 문제 제기 시 바로 중단(수집기 저장소에 명시), 광고를 붙이기 전 리그에 문의.
- **검증:** 수집한 결과로 다시 계산한 승 · 패 · 무가 7개 리그 모두 공식 순위와 일치했다.

## D-05 디자인: 토스 디자인 시스템 + 직접 그린 핵심 요소 (11/24)

- **고른 것:** 토스 디자인 시스템(TDS). 토스 안에서 열리는 앱이라 토스와 어울려야 한다. 범용 UI 라이브러리 10여 개는 웹 · 관리 화면 느낌이거나 무거워서 뺐다.
- **생긴 문제:** 부품을 그대로 쓰니 판정 영역 아래가 갑자기 평범해졌다("양산형").
- **해결:** 핵심 화면의 반복 요소는 직접 만들었다 — 팀 목록 → 팀 카드, 승패 도장 → 토스 거래내역처럼 큰 점수 + 작은 결과 글씨, 아래 선택창 → 화면 위 종목 · 팀 카드.
- **캐릭터:** 별 요정 등 후보를 비교해 **티켓 요정**을 골랐다. 직관 = 티켓이고, 판정을 티켓 상태(황금 티켓 · 구겨진 티켓 · 찢긴 티켓)로 표현할 수 있다.
- **로고:** 물건 하나(티켓) + 기호 하나(왕관), 실제 크기(48px)로 줄여 보고 판단했다. 파란 바탕에서 티켓 절취선이 묻혀 아이보리 바탕으로 바꿨다.

## D-06 지표: 대표 전환은 "직관 기록" (11/24)

- **고민:** 처음엔 카드 저장 · 공유를 대표 지표로 생각했다.
- **고른 것:** 대표 전환 = 직관을 기록한 사용자. 콘솔에서 대표 전환이 전환율 계산에 쓰인다는 것을 확인하고, 핵심 가치(판정)를 받는 행동으로 바꿨다. 자세히는 [출시와 운영](05_launch-and-operation.md).
