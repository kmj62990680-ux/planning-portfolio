# 03 AI가 한 것과 내가 판단한 것

| 항목 | 값 |
|---|---|
| 도구 | Claude Code(기획 정리 · 개발 · 시험), Gemini(캐릭터 · 로고 그림) |
| 원칙 | 코드 · 조사 · 초안은 AI, 무엇을 만들지 · 기준 · 확인 · 출시 판단은 내가 |

## 1. 단계별로 나누면

| 단계 | AI가 한 것 | 내가 한 것 |
|---|---|---|
| 소재 | 기존 앱 검색 | 직관 승리요정 아이디어, 종목 범위 결정 |
| 판정 기준 | 계산 구현, 이유 문장 초안 | "팀 성적 대비" 아이디어, 혼란을 보고 이유 문장을 넣기로 결정 |
| 경기 데이터 | 수집기 코드, 실행 환경(GitHub Actions) 구성 | "날짜를 고르면 결과가 자동으로", "경기가 끝날 시간에 맞춰 가져오기" 아이디어, 야구 · 축구 추가 결정 |
| 디자인 | 라이브러리 비교, 이미지 자르기 · 배경 지우기 | TDS 채택 승인, 티켓 요정 선택, 로고 바탕 변경 제안, "양산형" 판단 |
| QA | 자동 시험 작성 · 실행, 원인 추적 | 토스 앱에서 직접 써 보며 버그 발견(빈 길, 카드 저장), 고친 뒤 실기 확인 |
| 출시 · 지표 | 출시 규칙 정리, 지표 후보 | 검토 요청, 대표 지표 확정 |

## 2. AI 결과를 그대로 믿지 않은 곳

- **AI 예상이 틀린 곳:** 작은 아이콘은 이모지 글꼴이 낫다는 AI 판단 → 실제 크기로 넣어 보니 3D 그림이 더 잘 읽혀서 바꿨다.
- **크롬 시험만으로는 못 잡는 문제:** 승률 카드 저장은 크롬 시험을 통과했지만 토스 앱에서는 캐릭터가 빠졌다. 내가 토스 앱에서 확인하고 다시 고치게 하는 과정을 5번 반복했다. → [QA](04_qa.md)
- **데이터 검증:** 수집 결과를 공식 순위와 대조해 7개 리그 모두 일치하는 것을 확인한 뒤 공개했다.

## 3. AI에게 일을 맡기는 방식

- 결정 · 근거 · 실패를 그날그날 마크다운 노트로 남기고, AI가 다음 작업 전에 그 노트를 읽게 했다. 그래서 대화가 바뀌어도 같은 기준으로 이어서 만들 수 있었다.
- 오픈소스 도구를 쓸 때는 스타 수 · 라이선스를 먼저 확인했다(글꼴은 원본 파일을 수정 없이, 라이선스 전문 포함).
