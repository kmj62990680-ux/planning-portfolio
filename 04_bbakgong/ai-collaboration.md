# PM과 AI의 역할 분담

> AI 서비스에서 PM이 할 일은 모델을 만드는 것이 아니라,
> **어떤 기준으로 고르고, 무엇으로 검증하고, 비용을 어떻게 통제할지** 정하는 것이다.

## 1. 역할

| PM (나) | AI (Claude Code) |
|---|---|
| 서비스 방향, 대상, 기능 범위 결정 | 화면 · 서버 구현 |
| 모델 선택 기준과 검증 자료 결정 | 모델 비교 실행, 1차 채점 |
| 난이도 · 유형 · 비용 정책 결정 | 자동 시험 작성 · 실행 |
| 정책 · 법 근거 확인, 출시 판단 | 문서 조사, 검수 체크리스트 대조 |

## 2. PM이 내린 핵심 판단

### 모델 선택 기준을 먼저 세웠다
"4개 모델을 다 돌려 보고 차이가 없으면 가장 싼 것"으로 시작했다. 여기에 **정답 오류 0**을 넘어야 할 바닥선으로 뒀다.
결과적으로 가장 싼 모델은 기준을 넘지 못했고, 비용이 더 들더라도 정확한 모델을 택했다.

### 검증 자료를 올해 수능 시험지로 정했다
모델이 학습하기 전에 나온 시험이라 외운 답으로 점수를 속일 수 없다. 과목도 고르게 섞여 있다.
여기에 실제 수험생의 세법 교재 사진을 더해 손글씨와 형광펜이 있는 실제 상황도 시험했다.

### 해설도 품질 기준에 넣었다
처음 채점은 문제와 정답만 봤다. 사용자는 해설로 배우기 때문에 **해설 점수를 기준에 추가**했고, 그 결과 난이도 "빡공"이 해설까지 더 좋다는 것을 확인했다.

### "너무 쉽다"는 반응에 난이도와 유형을 열었다
난이도는 두 단계로만 열었다. 유형 선택은 유형별로 다시 검증해 정확도가 유지되는 것을 확인한 뒤 넣었다.

### 한도 대신 예산으로 통제했다
초기에는 사용자가 적으니 1인 횟수 제한을 없앴다. 대신 월 예산 상한과 자동 절약 모드, 과다 사용 알림을 둬 비용이 넘치지 않게 했다.

### 에이전트는 필요한 곳에만 쓴다
문제 만들기는 한 번 부르면 끝나는 일이라 에이전트를 쓰지 않았다. 여러 단계를 스스로 이어 가야 하는 "시험 D-day 복습 코치"를 에이전트 자리로 정했다.

## 3. AI 결과를 그대로 믿지 않았다

- **채점 검증:** 1차 채점은 다른 모델이 모델 이름을 가리고 했다. 계산 문제는 원본과 직접 대조해 다시 계산했고, 같은 자료를 두 번 채점해 점수가 흔들리지 않는 것을 확인했다.
- **정책 확인:** 중고생까지 대상을 넓히자는 안이 나왔지만, 앱인토스 공식 문서에서 "만 19세 이상" 정책을 확인하고 대상을 대학생 · 수험생으로 바로잡았다.
- **실제 기기:** 자동 시험과 별개로 토스 앱에서 사진 촬영부터 오답노트까지 직접 확인했다.
