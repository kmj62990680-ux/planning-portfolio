## 문서를 이렇게 관리합니다

기획 문서를 마크다운(md)으로 쓰고 깃허브에 둡니다.

- **문서를 ID로 엮습니다.** 요구사항(REQ) → 기능 → 정책 → 테스트가 서로의 ID를 가리킵니다. 저장소에서 ID 하나를 검색하면 관련 문서가 모두 나옵니다.
- **한 곳을 고치면 영향받는 문서를 바로 찾아 함께 고칩니다.** ID로 영향 범위를 찾고, AI 도구로 해당 문서들을 한 번에 반영한 뒤, 무엇이 바뀌었는지 변경 기록(CHANGELOG)에 남깁니다.
- **원본은 하나입니다.** 같은 내용을 여러 곳에 두지 않고, 규칙 · 기준값은 정책서 한 곳에 둡니다.
- **개발자는 필요한 문서만 AI 도구에 연결해 읽습니다.** 노션 · 시트에서 내보내 다시 넣는 과정이 없습니다.

이 방식은 프리패스에서 겪은 문제에서 나왔습니다. 프리패스 때는 문서 하나하나는 갖췄지만, 문서끼리 층 표기 · 우선순위가 어긋났습니다. 바꾸에서 위 방식으로 바꿨고, 같은 방식으로 프리패스 문서를 다시 정리해 [재정리본](02_freepass/rewrite/)으로 함께 올렸습니다.
