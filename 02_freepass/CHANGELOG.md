# 변경 기록

문서는 재정리본만 고친다. 원본(original/)은 바꾸지 않는다.

## v1.0 — 2026-11-18 재정리

프로젝트가 끝난 뒤(2026.07.30) 원본 5종을 다시 정리했다. 원본 내용을 새로 지어내지 않고, 원본끼리 어긋난 곳을 맞추고 흩어진 기준값을 모았다.

**구조**
- 개요(문제 정의 · 범위 · 우선순위 기준)를 새로 만들었다. 원본은 요구사항정의서 · 결과 보고서에 흩어져 있었다.
- 정책서를 새로 만들었다. 원본 기준값은 화면설계서 9장의 화면별 정책 기술 · 요구사항정의서 · 텍스트라이팅에 흩어져 있었다.
- 기능 명세를 화면별 진입 → 동작 → 조건 → 예외 → 결과로 묶었다. 원본은 예외가 테스트케이스에만 따로 있었다.
- 바꾸 기획 문서와 같은 형식으로 맞췄다: 폴더 구조, 문서마다 머리 표(버전 · 기준일 · 작성 기준 · 역할 · 연결), ID 사슬 REQ-영역-번호 → 기능 ID(A-01-1) → 정책 ID(P-01-01) → 테스트 ID. 원본 테스트케이스에는 기능 ID가 없었다.

**통일한 값** (자세한 표는 [정책서](docs/04_policy/policy.md) 맨 아래)
- 층: "2층" → 3층 맞이방 · 1층 승강장 (현장 기준)
- 음성: 화면설계서의 끌 수 있는 토글 → 상시 재생, 버튼 없음 (텍스트라이팅 · 테스트케이스 최종본)
- 본문 글자: 15sp · 18sp 혼재 → 18sp 이상
- 승강장 용어: "유리문 있는 곳" · "높은 승강장" 혼재 → 높은 · 낮은 승강장 (표지판)
- 위치 거부 분기: 요구사항(정적 안내)과 화면설계서(층 이동 안내)가 다름 → 권한 거부 = 정적 안내, 층이 아님 = 층 이동 안내

**우선순위** (기준: 7/30 최종 데모에서 동작했는가)
- 문자 진입 P1 → P0, 위치 없이 최소 안내 P2 → P0
- 지연 · 타는 곳 변경 재안내는 P2 유지, 관련 테스트 D-01~03을 상 · 중 → P2
- 출발 임박 테스트 F-01을 상 → P1 (기능 P1)

**삭제**
- 타는 곳 미확정 대기 화면(원본 FR-12 · E3). 문자가 확정 뒤에 가므로 생기지 않는 상태. 원본 테스트케이스 최종본에서도 이미 뺐다.

**정리**
- 원본 FR 번호 순서가 섞여 있어 REQ를 흐름 순서로 다시 매겼다. 원본 FR 번호는 대조용으로 남겼다.
- 원본 요구사항정의서 PDF에서 팀원 이름 한 곳을 가렸다.

**원본에서 결정하지 못한 채 끝난 것** (재정리본에서도 결정하지 않음)
- 승강장 표기에 "유리문 있는 · 없는 곳"을 함께 쓸지
- 발신명 "코레일 동행안내"와 화면 이름 "승강장 안내 서비스"를 하나로 할지
