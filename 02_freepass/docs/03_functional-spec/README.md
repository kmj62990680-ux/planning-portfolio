## 규칙

- **기능 ID = 요구사항 ID + 번호** (REQ-B-02 → B-02-1)
- **정책 ID** = 정책서 항목 (P-01-01 형식)
- **상태:** 확정 / 논의
- **우선순위:** P0 = 7/30 데모에서 동작 / P1 = 여유 시 / P2 = 설계 · 기록만
- **화면:** 원본 화면설계서 화면 번호 (S0~S6). 원본에 없는 화면은 E1 · E2
- **본문 양식:** 진입 → 동작 → 조건 → 예외 → 결과. 원본에서는 예외가 테스트케이스에만 따로 있었는데, 여기서는 기능마다 한 곳에 둔다
- **테스트:** 기능마다 연결된 테스트케이스 ID를 적는다 ([테스트케이스](../05_test-cases/test-cases.md))

## 흐름

```
S0 문자 → S1 서비스 시작 → S1-1 승차권 정보 확인 → S2 위치 권한
   → S3 현재 층 확인 → S4 탑승 정보 확인 → S5 경로 안내 → S6 도착
S2 거부 · 측위 실패 3회 ─→ E1 위치 없이 최소 안내
S3 "아니요"            ─→ S2-1 층 이동 안내 → S3
S5 지연 · 변경          ─→ E2 재안내 (P2, 미구현)
```
