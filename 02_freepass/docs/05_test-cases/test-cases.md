| 문서 역할 | 테스트케이스 = 기능이 명세대로 동작하는지 확인하는 상황 · 기대 결과 |
| 연결 | 케이스마다 "기능"으로 기능 명세서 ID를 가리킴. 원본에는 기능 ID가 없었다 |

## 규칙

- **TC ID:** 분류 + 번호. A 정상 경로 / B 위치 · 센서 / C 층 · 진입 / D 타는 곳 · 열차 / E 경로 · 이동 / F 시간 · 문자 / G 시스템 · 앱 상태 / H 도착 · 종료
- **우선순위:** P0 · P1 · P2. 원본의 상 · 중 · 하를 옮기되 **연결된 기능의 우선순위를 넘지 않는다.** 그래서 D-01~03(지연 · 타는 곳 변경)은 P2, F-01(출발 임박)은 P1이 됐다. 바뀐 곳은 "(원본)"에 원래 값을 적었다
- **기대 결과:** 화면 = 음성. {번호} = 타는 곳, {호차}, {가게} = 랜드마크
- 구성: 정상 15 + 예외 41. 제천역 현장 QA 3회, 회차마다 방향 센서 미동작 · 프로그램 멈춤을 찾아 고침
