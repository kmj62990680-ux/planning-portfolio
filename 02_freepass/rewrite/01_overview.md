# 01. 개요 — 문제 정의 · 목표 · 범위

> 프리패스 재정리본 v1.0 (2026-11-18). 원본(2026.06~07)에는 이 문서가 따로 없었고, 요구사항정의서 · 결과 보고서에 흩어진 내용을 한 곳에 모았다.

## 한 줄

열차를 예매한 고령층 이용객이 **문자 링크 하나로, 앱 설치 · 로그인 없이** 제천역 맞이방에서 정확한 타는 곳 · 호차 앞까지 화살표와 음성으로 안내받는 모바일 웹 서비스.

## 배경

| 항목 | 내용 |
|---|---|
| 과제 | 2026 미래내일 일경험 프로젝트형, 한국철도공사 충북본부 "고령층을 위한 AI 서비스" |
| 기간 | 2026.06 ~ 2026.07.30 (8주, 주제 선정부터 개발 · 현장 QA까지) |
| 팀 | PM(본인, 팀장) · 백엔드 1 · 프론트엔드 1 · 디자이너 1 |
| 결과 | 최종 발표 최우수상(2026.07.30). 이후 한국철도공사에서 서비스 고도화 진행 중 |

## 문제 정의

조사 순서: 민원 자료 분석 → 인터뷰지 작성 → 서울역 · 제천역 현장 인터뷰(고령층 이용객 16명, 역 직원 5명) · 행동 관찰.

- 처음 가설은 "고령층은 승차권 예매가 가장 어렵다"였다. 현장에서는 **예매는 대부분 해냈고, 예매 이후 타는 곳을 찾는 단계에서 막혔다.**
- 제천역은 3층 맞이방에서 1층 승강장으로 내려가는 구조이고, 같은 번호의 타는 곳 안에서도 높은 승강장(고상홈) · 낮은 승강장(저상홈)이 나뉜다.
- 역 안내는 "고상홈 · 저상홈" 같은 전문용어와 작은 표지판 중심이라 고령층이 바로 이해하기 어렵다.
- 새 앱을 설치하고 가입 · 로그인하는 과정 자체가 큰 부담이다.

> 민원 자료 원문과 역 구조 자료(도면 · 피난안내도 · 경로 수치)는 **코레일 내부자료라 공개하지 않는다.**

## 해결 방향

| 문제 | 해결 | 요구사항 |
|---|---|---|
| 앱 설치 · 로그인 부담 | 출발 15분 전 문자 링크 → 모바일 웹 즉시 시작 | REQ-01 |
| 층 구조가 복잡함 | 시작 층(3층 맞이방)을 사용자 확인으로 맞추고 시작 | REQ-02 |
| 같은 번호 안에서도 탈 위치가 다름 | 높은 · 낮은 승강장 구분 + 호차 위치까지 안내 | REQ-05 |
| 전문용어 · 작은 표지판 | 표지판과 같은 쉬운 말 + 화살표 + 음성 상시 안내 | REQ-07 · 08 |

## 범위

**포함:** 문자 진입, 승차권 정보 확인, 위치 권한 · 층 확인, 탑승 정보 확인, 실시간 경로 안내, 승강장 · 호차 안내, 도착, 위치 없이 최소 안내.

**포함하지 않음:**
- 역까지 오는 길(역 밖 길찾기)
- 승차권 예매 · 결제
- 앱 설치 · 회원가입
- 타는 곳 미확정 대기 화면 — 문자가 타는 곳 확정 뒤(출발 15분 전)에 가므로 진입 시점에는 항상 타는 곳이 정해져 있다
- 타는 곳 변경 · 지연 재안내 — 설계만 하고 7/30 데모에서는 구현하지 않았다(P2)

## 우선순위 기준

- **P0** = 7/30 최종 데모에서 동작한 기능
- **P1** = 설계했고 여유가 있을 때 하는 기능
- **P2** = 설계 · 기록만 한 기능

테스트케이스 우선순위는 기능 우선순위를 넘지 않는다(P2 기능의 테스트를 P0로 두지 않는다).
