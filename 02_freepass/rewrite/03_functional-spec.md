# 03. 기능 명세

> 재정리본 v1.0 (2026-11-18). 원본 [화면설계서 9장 (2026-07)](../original/03_화면설계서_9장_2026-07.pdf)의 화면별 정책 기술 · 분기를 기능 단위로 다시 묶었다. 원본에서는 예외가 [테스트케이스](../original/04_테스트케이스_56건_2026-07.pdf)에 따로 있었는데, 여기서는 기능마다 진입 → 동작 → 조건 → 예외 → 결과로 한 곳에 둔다.

## 흐름

```
S0 문자 → S1 서비스 시작 → S1-1 승차권 정보 확인 → S2 위치 권한
   → S3 현재 층 확인 → S4 탑승 정보 확인 → S5 경로 안내 → S6 도착
S2 거부 · 측위 실패 ─→ E1 정적 안내 (위치 없이 최소 안내)
S3 "아니요" ─→ S2-1 층 이동 안내 → S3
S5 지연 · 변경 ─→ E2 재안내 (P2, 미구현)
```

---

## S0 문자 진입 · REQ-01 · P0

- **진입:** 타는 곳이 확정되는 시점(출발 15분 전)에 서버가 1회 발송한다.
- **동작:** 문자에 열차 정보와 공식 도메인 링크를 담는다. 링크를 누르면 S1이 열린다.
- **조건:** 공식 발신번호 · 공식 도메인만 쓴다(P-01).
- **예외:** 링크 만료 후 접속 → "안내가 종료된 열차예요." (TC F-04)
- **결과:** 앱 설치 · 로그인 없이 S1로 들어온다.

## S1 서비스 시작 · REQ-01 · P0

- **진입:** 문자 링크.
- **동작:** "타는 곳까지 안내해 드릴게요."를 표시하고 음성으로 읽는다. [시작하기]를 누르면 승차권 토큰을 조회한다.
- **조건:** 네트워크 요청 없이 바로 그린다. 흰 화면이 3초 넘게 보이면 고장 난 줄 알고 떠나기 때문이다(NFR-04).
- **예외:** 토큰 조회 실패 → "승차권 정보를 불러올 수 없습니다." [다시 시도]
- **결과:** S1-1.

## S1-1 승차권 정보 확인 · REQ-01 · P0

- **진입:** S1 [시작하기].
- **동작:** 링크 토큰으로 구간 · 시각 · 열차 · 타는 곳 · 호차 · 좌석을 채운다. [안내 시작]을 누르면 세 단계로 검증한다: ① 승차권 토큰 유효 → ② 위치 권한 → ③ 측위 신뢰도.
- **조건:** 별도 로그인 · 본인인증 없음. 승차권번호는 뒤 4자리만 보인다(P-02).
- **예외:**
  - 토큰 만료(출발 시각 + 30분) → 다른 어떤 검증보다 먼저 막는다. 만료된 승차권으로 안내를 시작하면 엉뚱한 승강장으로 갈 수 있다.
  - 권한 없음 → S2
  - 측위 신뢰도 부족 → S3 (사용자 확인으로 시작 위치를 맞춤)
- **결과:** 모두 통과하면 S4.

## S2 위치 권한 요청 · REQ-02 · P0

- **진입:** S1-1에서 권한이 없을 때.
- **동작:** OS 팝업 전에 "왜 위치가 필요한지"를 먼저 설명한다. [위치 허용]을 누르면 브라우저 권한 팝업이 뜬다.
- **조건:** 권한을 얻기 전에는 지도에 내 위치를 표시하지 않는다.
- **예외:** 거부 → E1 정적 안내. 서비스를 끝내지 않는다. 보류([나중에]) → "위치를 켜면 길을 안내해 드릴 수 있어요." (TC B-02)
- **결과:** 허용 → S3.

## S3 현재 층 확인 · REQ-02 · P0

- **진입:** S2 허용 후, 또는 S1-1에서 측위 신뢰도가 낮을 때.
- **동작:** "지금 3층 맞이방에 계신가요?" [네] / [아니요]
- **조건:** GPS는 위경도만 주고 실내에서 층(고도)은 믿을 수 없어서, 층은 사용자에게 확인한다. 이미 권한을 줬는데 왜 또 묻는지 보조 문구로 설명한다.
- **예외:** [아니요] → S2-1 층 이동 안내, 왕복 횟수 +1. 왕복이 2회를 넘으면 층 확인을 건너뛰고 S4로 가되, 안내가 부정확할 수 있다고 화면에 알린다(P-04).
- **결과:** [네] → S4.

## S2-1 층 이동 안내 · REQ-02 · P0

- **진입:** S3 [아니요].
- **동작:** "3층 맞이방으로 올라와 주세요. 에스컬레이터가 앞에 있어요." 좌 · 우 대신 랜드마크로 말한다. 실제 촬영 이미지를 함께 보여 준다.
- **조건:** 목표 층은 역별 고정 데이터에서 가져온다. 실시간 측위와 무관하다.
- **예외:** 사용자가 실제로 올라오지 않고 버튼을 눌러도 확인할 방법이 없다 → S3의 왕복 제한으로 막는다.
- **결과:** [올라왔어요] → S3.

## S4 탑승 정보 확인 · REQ-03 · P0

- **진입:** S3 [네].
- **동작:** 타는 곳 번호를 크게 보여 주고 호차를 고른다. [길찾기 시작]을 누르면 현재 노드에서 목적지 노드까지 최단 경로를 찾는다.
- **조건:** 타는 곳은 승차권 값이라 바꿀 수 없다. 호차는 승차권 값이 기본이고 바꿀 수 있다(동행자와 좌석이 떨어진 경우).
- **예외:** 승차권과 다른 호차를 고르면 확인 팝업을 띄운다(P-07). 호차 정보가 없으면 타는 곳까지만 안내한다(TC D-04).
- **결과:** S5.

## S5 경로 안내 · REQ-04 · REQ-05 · P0

- **진입:** S4 [길찾기 시작].
- **동작:** 한 화면에서 네 가지 상태를 바꿔 가며 보여 준다: 직진 / 좌 · 우회전 / 계단 · 에스컬레이터 · 엘리베이터 / 승강장 진입. 화살표 + 남은 거리 + 단계 문구 + 음성을 함께 낸다. 승강장에 들어서면 높은 · 낮은 승강장과 호차 위치를 안내한다.
- **조건:** 남은 거리는 다음 분기점까지의 거리(P-05). 상단 정보바(출발 시각 · 타는 곳 · 호차 · 좌석)는 S4~S6에서 고정된다.
- **예외:**
  - 측위 실패 3회 연속 → 안내를 멈추고 E1 정적 안내로 넘어간다. 잘못된 화살표는 안내가 없는 것보다 위험하다.
  - GPS 약함 → "잠시만요, 지금 계신 곳을 확인하고 있어요." 좌표 튐 → 직전 안내 유지.
  - 방향센서 없음 → "화살표 대신 글과 음성으로 안내할게요."
  - 경로 이탈 · 반대편 승강장 · 지나침 → 재안내 문구 (TC E-01 · 07 · 08)
  - 엘리베이터 안 신호 끊김 → "엘리베이터에서 내리면 이어서 안내할게요."
  - 출발 5분 전 → 색 · 아이콘 · 문구를 함께 바꿔 강조(P1, P-08)
- **결과:** 도착 판정 반경에 들어오면 S6.

## S6 도착 · REQ-06 · P0

- **진입:** 목적지 노드 반경 5m 안(P-06).
- **동작:** "다 왔어요. 여기서 O호차를 기다리세요." 화면 변화 + 음성 + 진동을 동시에 낸다. 호차 번호를 다시 보여 준다. 목적은 "도착"이 아니라 "올바른 호차 앞"이다.
- **조건:** 자동으로 닫지 않는다. 닫으면 승강장에서 정보를 다시 볼 방법이 없다.
- **예외:** 잘못된 승강장 도착 → "여기가 아니에요. O번 타는 곳으로 안내할게요." (TC H-03)
- **결과:** 사용자가 [안내 종료]를 누른다.

## E1 정적 안내 (위치 없이 최소 안내) · REQ-09 · P0

- **진입:** S2 권한 거부, 또는 S5 측위 실패 3회 연속.
- **동작:** "위치 없이 알려드릴게요. O번 타는 곳, O호차, 높은 승강장입니다."를 큰 글자 + 음성으로 낸다. 실시간 화살표는 없다.
- **결과:** 최소 안내로 끝난다.

## E2 지연 · 타는 곳 변경 재안내 · REQ-11 · P2 (설계만, 데모 미구현)

- **진입:** S5 진행 중 또는 도착 후 지연 · 변경 이벤트.
- **동작:** 화면 전환이 아니라 팝업으로 알리고 S5 경로를 새로 그린다. 떨어진 타는 곳으로 바뀌면 층 이동(엘리베이터로 3층 → 목표 승강장)을 포함해 다시 안내한다.
- **조건:** 모든 승강장 사이의 이동 경로를 미리 데이터로 가지고 있어야 한다.
