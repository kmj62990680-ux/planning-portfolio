## 처음 보는 사람은 이 순서로

1. [개요](docs/01_overview/overview.md): 왜 만들었는지, 어디까지 만드는지, 우선순위 기준
2. [기능 명세서](docs/03_functional-spec/README.md): 흐름도와 기능 목록을 보고, 영역 파일(A~D, X)에서 기능별 진입 → 동작 → 조건 → 예외 → 결과
3. 여러 기능에 걸친 규칙 · 숫자는 [정책서](docs/04_policy/policy.md). 맨 아래 "원본끼리 달랐던 값"에서 무엇을 통일했는지 볼 수 있다
4. 원본과 비교하려면 [original/](original/)의 화면설계서 · 테스트케이스

- 기능 ID(예: `C-02-1`)를 저장소 검색창에 넣으면 관련 문서가 모두 나온다

## ID 규칙

```
요구사항  REQ-C-02   →  기능  C-02-1   →  정책  P-03-01   →  테스트  E-01
          (영역-번호)       (요구사항-세부)      (분류-번호)          (분류-번호)
```

- 영역: A 진입 / B 위치 · 층 확인 / C 길찾기 / D 도착 / X 공통 / N 비기능
- 화면 번호(S0~S6)는 원본 화면설계서의 화면 이름과 같습니다

## 공개하지 않는 자료

다음은 **코레일 내부자료라 공개할 수 없습니다.**

- 민원(VOC) 자료
- 역 도면 · 피난안내도, 이를 바탕으로 만든 경로 노드 좌표 · 거리 수치
- 코레일 담당자와 주고받은 간격 · 구조 문의 자료

인터뷰 응답 원문과 팀원 개인 정보도 올리지 않습니다.
